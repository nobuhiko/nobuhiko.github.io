EC-CUBE と PHP のバージョン対応表

PHP の脆弱性「PHP2Shell」は、特別な扱いになりました。サポートの終わった PHP 5 系からの古いバージョンにも修正が出て、国内のレンタルサーバーの多くが入れ終えています。EC-CUBE 4.2 系・4.1 系・4.0 系のお店が使う PHP に入ったかどうかは、サーバーによります。お使いのサーバーのお知らせを読んで確かめましょう。

これは PHP2Shell にかぎった対応です。サポートの終わった PHP には、ふつうは新しい修正が出ません。このページでは、PHP2Shell の修正が自分のお店に入ったかを確かめる方法と、そのあとの PHP の上げ方をまとめます。

2 つの表を重ねると

  • EC-CUBE 4.3 系で、PHP 8.2 か 8.3 のお店: PHP が 8.2.35 か 8.3.36 以上になっていれば、修正は入っています。番号がそれより前でも、サーバー会社が番号を変えずに修正を入れていることがあります。そのときは、下の 1 〜 5 の順で確かめます。
  • EC-CUBE 4.3 系で、PHP 8.1 のお店: PHP を 8.2 か 8.3 に切り替えられます。切り替える前に、入れているプラグインがその PHP で動くかを確かめます。
  • EC-CUBE 4.2 系・4.1 系・4.0 系のお店: PHP 7.4 〜 8.1 などに修正が入ったかどうかは、サーバーによります。お使いのサーバーのお知らせを読んで確かめます。下の 1 〜 5 の順です。

番号が修正版より前のお店が、確かめること

1. PHP の番号では決めない。サーバー会社が入れた修正は、番号に出ないことがあります。サポート中の 8.2 以上でも同じです。たとえば ConoHa WING の PHP は、7.4.33・8.0.30・8.1.34・8.2.34・8.3.35 のまま、どれも 2026 年 10 月 21 日の夜に作り直されていました(2026 年 11 月 15 日に、契約しているサーバーで確かめました)。エックスサーバーは、PHP 5.1 〜 8.1 にも修正を入れ、バージョンの表示は変えていないと発表しています。

PHP が作られた日は、phpinfo の「Build Date」で見られます。公表の日(2026 年 10 月 21 日)より前の日付なら、まだ作り直されていません。後の日付なら作り直されていますが、それだけでは修正が入ったとは言い切れないので、次の 2 か 3 で確かめます。

2. レンタルサーバーなら、サーバー会社のお知らせを読む。「PHP の脆弱性への対応」のようなお知らせに、どのバージョンに修正を入れたかが書かれています。国内の多くの会社が、2026 年 10 月 22 日から 26 日のあいだに、PHP 5 系までさかのぼって修正を入れ終えたと発表しています。自分のお店が使っている PHP が、そこに入っているかを見ます。

3. VPS やクラウドなら、自分で更新する。PHP の更新は、借りている側の作業です。OS の配布元(Ubuntu、AlmaLinux など)が出している更新を、自分か、管理を頼んでいる会社が入れます。

4. お知らせが見つからなければ、尋ねる。そのまま送れる文です。

5. 修正が入るまでの、当面の対策。PHP の公式のお知らせは、session.upload_progress.enabled=0 にして PHP を再起動する、などの設定を挙げています。php.ini かサーバーの設定に入れるもので、ini_set() や .user.ini では効かないと書かれています。危なさを減らす設定で、修正の代わりにはならないとも書かれています。

PHP2Shell のあと: サポートの終わった PHP を、どうするか

PHP 8.1 以前は、PHP 本体のサポートが終わっています。PHP2Shell では特別に修正が出ましたが、次に見つかる脆弱性でも同じ対応になるとは限りません。サポート中の PHP(8.2 以上)に移るには、EC-CUBE を 4.3 系に上げます。

4.2 系から 4.3 系のように系列をまたぐバージョンアップは、カスタマイズした部分と、入れているプラグインが新しい系列で動くかを、1 つずつ確かめながら進めます。

順番としては、先に上の 1 〜 5 で「いまの PHP が安全か」を確かめます。次に、同じ系列のいちばん新しい修正版(4.2.1 → 4.2.3 など)まで上げます。4.3 系へは、そのあと計画して進めます。

よくある質問

EC-CUBE 4.2 が対応する PHP のバージョンは?
EC-CUBE 4.2 系が対応する PHP は 7.4 〜 8.1 です。PHP 8.2・8.3 には、EC-CUBE 4.3 系が対応しています。

PHP 8.1 以前には、PHP2Shell の修正は入りますか?
サーバーによります。PHP 7.4・8.0・8.1 には、PHP の開発チームが修正のソースを GitHub で提供していて、それを入れるかどうかは、レンタルサーバーや OS の配布元が決めます。PHP 7.3 から 5 系に、自社で修正を入れた会社もあります。バージョンの番号は変わらないので、お使いのサーバーのお知らせを読んで確かめます。これは PHP2Shell にかぎった特別な対応です。

PHP のバージョンの番号を見れば、修正が入っているか分かりますか?
番号が 8.2.35、8.3.36、8.4.27、8.5.12 以上なら、入っています。それより前の番号では、番号だけではどちらとも言えません。番号を変えずに修正を入れるサーバー会社が多いためです(サポート中の 8.2 以上でも同じです)。サーバー会社のお知らせを読むか、問い合わせて確かめます。

自分のお店がどれに当たるかを、プラグインで確かめる

うみうしラボの「脆弱性を AI で診断・修正するプラグイン」(EC-CUBE 4.2 系・4.3 系)は、ここまでの内容を、お店の中で代わりに確かめます。

  • 無料のかんたん点検: EC-CUBE 本体とプラグインが、公式の修正が入ったバージョンかどうかを確かめます。PHP のサポートの期限と、PHP を上げたときに止まるプラグインも、先に洗い出します。
  • 有料の点検と直し: PHP の番号だけで決めずに、配布元の記録と、PHP が作られた日を読んで、修正が入っているかを見分けます。サーバー会社に送る文も、報告に付けます。
